# AHC 用 貪欲法ライブラリ

**単一ファイル・コピペ可能**な貪欲法テンプレート集です。`main.cpp` の「■ 問題ごとに書き換える部分」
だけを書き換えれば動きます。パラメータは環境変数経由で **optuna + pahcer** から自動調整できます。

```
greedy/
├── 1_greedy/              毎回一番良い手を選ぶ（＋評価値ノイズで時間いっぱい繰り返す）
├── 2_insertion_greedy/    過去改変貪欲（末尾だけでなく操作列の途中にも挿入できる）
├── 3_rolling_horizon/     貪欲プレイアウト（各候補の先を貪欲で進めて結果が最良の手を採用）
│    ├── main.cpp / optimize.py / pahcer_config.toml
└── tools/gen.py
```

---

## 1. すぐ動かす

デモは **価値付き巡回（orienteering）**。N 地点それぞれに価値があり、地点 0 から出発して 0 に戻る
総距離 LIMIT 以下の経路で、訪問した地点の価値合計を最大化します。

```bash
cd 2_insertion_greedy
g++ -std=c++20 -O2 -o a.out main.cpp
./a.out < /dev/null > /dev/null
# Score = 4034
# trials = 2421, steps = 166609, time = 1900.3 ms
# [check] running = 4034 / replay = 4034
```

`[check]` は実装のバグ検出用（積み上げたスコアと出力再生スコアの一致＋制約違反チェック）です。

## 2. 3 つの手法と効果

| | 手法 | どういう時に使うか |
|---|---|---|
| 1 | 貪欲 | **まず最初に書く**。最速。他の手法の初期解・rollout 方策としても使い回せる |
| 2 | 過去改変貪欲 | 解が「操作の列」で、途中に差し込めると得をする問題（経路・スケジュール等） |
| 3 | 貪欲プレイアウト | 「今の手が後で効いてくる」問題。目先の評価だけでは詰むのを避けたいとき |

デモ（3 ケース合計、価値の合計なので**大きいほど良い**、1 ケース 1.9 秒）：

| 手法 | スコア合計 | 単純貪欲比 |
|---|---|---|
| 1 貪欲（ランダム多点） | 9872 | — |
| 2 過去改変貪欲 | **14144** | **+43%** |
| 3 貪欲プレイアウト | 10040 | +2% |

> このデモでは「途中に挿入できる」ことの効果が圧倒的でした。
> **どれが勝つかは問題次第**なので、同じ問題定義を 3 つのフォルダにコピーして比べてください。
> 1 と 3 は**インターフェースが完全に同じ**なので、1 で書いたものをそのまま 3 に貼れます。

## 3. 書き換えるのはここだけ

### 1_greedy / 3_rolling_horizon（共通インターフェース）

```cpp
struct Move  { ... };                          // 手
struct State { float score; ... };             // ★float score 必須
void  init_state(State &s);                    // 初期状態
int   enum_moves(const State &s, Move *out);   // 今選べる手を全列挙（0 を返したら終了）
float eval_move (const State &s, const Move &mv);  // ★貪欲の評価値（大きいほど先に選ぶ）
float calc_score(const State &s, const Move &mv);  // その手で確定するスコア差分
void  apply_move(State &s, const Move &mv);        // 手を適用する（score は触らない）
```

**`eval_move` がスコア差分と違って良い**のが重要です。デモでは「価値 ÷ 増える距離^ALPHA」という
コスパを評価値にしています。ここの設計が貪欲の強さのほぼ全てで、`ALPHA` などを optuna で詰めます。

### 2_insertion_greedy

```cpp
int   enum_items (const State &s, Move *out);              // まだ使っていない要素
int   seq_len    (const State &s);                         // 操作列の長さ（挿入位置は 0〜これ）
float eval_insert(const State &s, const Move &mv, int pos);// pos に挿入した評価値（不可なら WORST_SCORE）
float calc_score (const State &s, const Move &mv, int pos);// 挿入で確定するスコア差分
void  apply_insert(State &s, const Move &mv, int pos);     // 挿入を実行する
```

1 挿入あたり O(残り要素数 × 列の長さ) かかります。ここが重い場合は
**挿入位置を「近い方から数箇所」に絞る**と、質をほぼ落とさず大幅に速くなります。

## 5. パラメータ調整（optuna + pahcer）

| キー | 意味 |
|---|---|
| `p1` `ALPHA` | 評価関数の重み（**問題ごとの評価関数のパラメータに置き換える**） |
| `p2` `EPS_DIST` | 0 除算よけ |
| `p3` `NOISE` | ランダム貪欲のノイズ幅。**0 なら決定的な貪欲 1 回で終了**、>0 なら時間いっぱい繰り返して最良解を採用 |
| `p3` `HORIZON` (3 のみ) | プレイアウトの手数（-1 で最後まで） |
| `p4` `NOISE` (3 のみ) | プレイアウトのノイズ幅 |

```bash
python3 tools/gen.py 0 20
cd 2_insertion_greedy && python3 optimize.py
```

**ノイズ付きランダム多点貪欲**（`NOISE > 0`）はほぼ無条件で得をします。決定的な貪欲は
「一箇所の判断ミス」を引きずりますが、ノイズを入れて何万回も回せば引き直せるためです。
デモでは 1.9 秒で 76502 回の貪欲を回しています。

## 6. 高速化のためにやっていること

| 箇所 | 内容 |
|---|---|
| 候補の選択 | ソートせず**最大のものを 1 パスで拾う**だけ（O(候補数)） |
| メモリ確保 | State・候補配列はすべて静的確保。ループ中に `malloc` を一度も呼ばない |
| 繰り返し | 決定的な貪欲を 1 回回した後、ノイズ付きで時間いっぱい繰り返して最良解を採用 |
| 時間計測 | rdtsc / cntvct 直読み。1 試行に 1 回だけ |
| プレイアウト | State のコピーは候補ごとに 1 回だけ（コピー元は使い回す） |

## `[check]` について

貪欲は「選んだ手」でしか `calc_score` を呼ばないので、差分計算の誤りは必ず
`[check]`（積み上げたスコア 対 出力を再生した真のスコア）に現れます。
焼きなましのように「却下された手の差分が間違っている」という隠れ方をしないため、
このライブラリには追加の検証は入れていません。

`eval_move` は順位付け用のヒューリスティックで、真のスコアと一致する必要が無いので検査対象外です
（そこが貪欲の設計の自由度であり、腕の見せ所でもあります）。

## 7. 注意点

- **`MAX_CAND`**：1 手で選べる候補の最大数。配列サイズに直結するので必ず正しい値にしてください。
- **貪欲は他の手法の土台**：ここで書いた `eval_move` は、モンテカルロの rollout 方策や
  ビームサーチの評価関数、焼きなましの初期解生成にそのまま使い回せます。
- **`NOISE = 0` だと 1 回で終わる**：時間が余るので、必ず `NOISE > 0` を試してください。
